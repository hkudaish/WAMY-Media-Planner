# لوحة متابعة الخطة الزمنية — WAMY & إمعان

تطبيق محلي لمتابعة عقد التواصل الاستراتيجي 2026–2027. يعمل عبر خادم Node.js واحد، ويحفظ البيانات والحسابات في PostgreSQL محلي. المتصفح لا يتصل بقاعدة البيانات مباشرة ولا يحتوي على بيانات اتصال بها.

## المتطلبات

- Node.js 20 أو أحدث
- PostgreSQL 14 أو أحدث يعمل على الجهاز

## التشغيل لأول مرة

أنشئ قاعدة بيانات فارغة باسم `media_project_planner`:

```sql
create database media_project_planner;
```

ثم من مجلد المشروع:

```bash
npm install
cp .env.example .env
npm run db:init
npm start
```

على Windows PowerShell استخدم `Copy-Item .env.example .env` بدل أمر `cp`.

افتح <http://localhost:5175>. أول حساب يُنشأ يصبح مدير النظام النشط تلقائيًا.
بعد ذلك يستطيع المدير من «إعدادات النظام ← المستخدمون والصلاحيات» إضافة
المستخدم وتحديد دوره وصلاحياته، ثم نسخ رابط تسجيل خاص أو مشاركته بالبريد
وواتساب أو قائمة المشاركة في الجهاز. يختار المستلم كلمة مروره بنفسه ويُفعّل
الحساب عند قبول الدعوة.

## إعداد الاتصال

اتصال PostgreSQL موجود في ملف `.env` على الخادم فقط:

```dotenv
DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/media_project_planner
PORT=5173
NODE_ENV=development
PUBLIC_ORIGIN=http://localhost:5175
INVITATION_HOURS=168
```

عدّل اسم المستخدم وكلمة المرور والمنفذ بحسب إعداد PostgreSQL المحلي لديك. ملف `.env` مستبعد من Git ولا ينبغي نسخه إلى المتصفح أو رفعه إلى مستودع.
يجب أن يطابق `PUBLIC_ORIGIN` عنوان التطبيق الذي يصل إليه المستخدمون، لأنه
يُستخدم في إنشاء روابط الدعوات. مدة الرابط الافتراضية 168 ساعة، ويمكن
تعديلها عبر `INVITATION_HOURS` ضمن نطاق ساعة إلى 720 ساعة. لا تُخزّن رموز
الدعوات نفسها في قاعدة البيانات؛ تُخزّن تجزئتها فقط، وكل رابط أحادي الاستخدام.

## الأوامر

```bash
npm run db:init   # إنشاء/ترقية الجداول وزرع منتجات الخطة (آمن للتكرار)
npm start         # تشغيل التطبيق على http://localhost:5173
npm run dev       # تشغيل مع إعادة تحميل الخادم عند تعديل الملفات
npm run check     # فحوص بنيوية سريعة لمسار الاتصال والحماية
npm run build     # إنشاء حزمة الواجهة المحسّنة للإنتاج داخل dist
npm run test:security # اختبار عزل الجهات والصلاحيات وسجل التدقيق
npm run test:attached-plan # التحقق من اكتمال ملف WAMY ودورة Excel ذهابًا وإيابًا
npm run test:master-plans # اختبار المشاريع وخط الأساس وربط المهام والتنبيهات
npm run test:task-workflow # اختبار تسلسل المهمة وتعدد المسؤولين وسجل التزمين
npm run test:user-invitations # اختبار إنشاء المستخدم وقبول الدعوة والصلاحيات
npm run master-plan:convert # إعادة توليد قوالب المشاريع المعتمدة
npm run db:backup # إنشاء نسخة PostgreSQL احتياطية مشفرة عند ضبط المفتاح
npm run db:restore:test # اختبار أحدث نسخة داخل قاعدة مؤقتة ثم حذفها
```

## النشر الإنتاجي

تعليمات Docker، وHTTPS، والأسرار، وإنشاء المستخدم الأول، والنسخ الاحتياطي
المشفّر، واختبار الاستعادة، والمراقبة موثقة في [DEPLOYMENT.md](DEPLOYMENT.md).
لا تستخدم ملف `.env` المحلي في الإنتاج، ولا تنشر PostgreSQL أو منفذ Node
مباشرة على الإنترنت.

يعرض `GET /api/health` حالة اتصال الخادم بقاعدة البيانات.

## المعمارية والحماية

- `code_artifact.html`: واجهة التطبيق، وتتصل بمسارات `/api` من نفس الخادم فقط.
- `server.js`: المصادقة، الجلسات، الصلاحيات وطلبات PostgreSQL المعلّمة.
- `database/schema.sql`: الجداول والأنواع والمشغّلات والبيانات الأولية.
- `scripts/init-db.js`: تطبيق المخطط على قاعدة الاتصال المحددة في `.env`.
- كلمات المرور تُجزّأ بـ bcrypt ولا تعاد إلى الواجهة.
- رموز الجلسة العشوائية تُخزن في Cookie من نوع `HttpOnly` و`SameSite=Strict`، ولا تُحفظ إلا تجزئتها في PostgreSQL.
- الخادم يعيد فحص حالة الحساب ودوره وصلاحياته في كل طلب؛ إخفاء أزرار الواجهة ليس حاجز الحماية الوحيد.
- مشغّل قاعدة البيانات يمنع تعطيل أو حذف آخر مدير نشط.
- التحديثات بين النوافذ المفتوحة تُجلب دوريًا كل 10 ثوانٍ وعند العودة إلى النافذة.

### الصلاحيات ونطاق البيانات

يدعم النظام أدوار مدير النظام، والمشرف، ومدير المشروع، ومدير الإدارة، وقائد
الفريق، والموظف، والمراجع، والمعتمد، والقراءة فقط. لا يمنح اسم الدور وحده
أي إجراء (باستثناء مدير النظام)؛ تُحدد صلاحيات العرض والإجراءات بصورة مستقلة
لكل شاشة. كما يحدد لكل مستخدم نطاق بياناته: بياناته، أو فريقه، أو إدارته، أو
مشروع يديره، أو كل البيانات. تطبق القيود في القائمة والشاشة والأزرار وفي API،
وتسجل محاولات الوصول المرفوضة في سجل التدقيق. تظهر تغييرات الصلاحيات في
الجلسة المفتوحة خلال 10 ثوانٍ كحد أقصى أو فور العودة إلى نافذة التطبيق.

## Google Drive

تكامل Google Drive اختياري ومستقل عن اتصال PostgreSQL. تضبط بيانات المتصفح العامة من «إعدادات النظام»، وتُحفظ في جدول `app_settings`. لا تخزن Client Secret أو مفتاح حساب خدمة في التطبيق.

## استيراد الخطط من Excel

من شاشة «المهام والمتابعة»:

1. اضغط «تنزيل نموذج خطة» للحصول على نموذج XLSX محدث بقوائم المنتجات المتاحة والمستخدمين النشطين.
2. أدخل مهمة في كل صف مع الحفاظ على أسماء الأعمدة.
3. اضغط «إضافة خطة جديدة»، وارفع الملف لعرض المعاينة والأخطاء والتكرارات.
4. اعتمد الصفوف الصحيحة؛ تضاف فقط سجلات جديدة ولا تتأثر البيانات الحالية.

يدعم الاستيراد تنسيقين بصيغة XLSX: نموذج الخطة الحديث ذي 12 عمودًا، وملف
WAMY ذي ورقة «المهام» والأعمدة العشرة (`م` حتى `الوضع الزمني`). يحافظ
التنسيق الثاني على المنتج الفرعي، ووصف المهمة، والتاريخ، والحالة، والفئة،
والمسؤول والملاحظات. ومن شاشة «التقارير» يمكن تنزيل ملف Excel بنفس تنسيق
الأعمدة العشرة، متضمنًا كل المهام المتاحة للمستخدم وحقول الجدول المحسوبة.

يمكن ضبط «السماح بإنشاء مهام متعددة للمنتج» و«المنتج نشط» من نافذة تعديل المنتج. المنتجات المكتملة أو المعتمدة أو الملغاة أو المؤرشفة أو غير النشطة لا تظهر عند إنشاء مهمة أو تنزيل النموذج.

## الخطة الرئيسية والمشاريع

يستطيع مدير النظام من شاشة «الخطة الرئيسية» إنشاء مشروع مستقل أو استيراد
قالب WAMY ذي 24 عمودًا. تُحفظ بنود خط الأساس في جدول مستقل عن المهام
التنفيذية، مع رمز المشروع، والتسلسل الأبوي، والمسار، والمرحلة، والمواعيد،
والكميات، والمؤشرات والمستهدفات. إنشاء المهمة مسار من ثلاث مراحل: اختيار
المشروع ثم أحد منتجاته فقط، إدخال التفاصيل والتزمين، ثم إسنادها إلى مسؤول
واحد أو أكثر من المستخدمين النشطين في جهة المشروع. ينسخ النظام تزمين المنتج
كتزمين افتراضي قابل للتعديل دون المساس بخط الأساس، ويسجل كل تعديل مع المنفذ
والوقت والسبب والقيم السابقة والجديدة. عندها يقارن النظام تاريخ المهمة
بخط الأساس ويعرض التأخير والانحراف ونسب الإنجاز والتنبيهات في شاشة الخطة
وفي التقرير التنفيذي.

القوالب الثلاثة الجاهزة للاستيراد موجودة في مجلد `converted-plans/`. إعادة
استيراد القالب نفسه تحدّث البنود المطابقة اعتمادًا على رمز المشروع ومعرف
السجل ولا تنشئ نسخًا مكررة.

## النسخ الاحتياطي

للتطوير المحلي فقط، يمكن استخدام أدوات PostgreSQL المعتادة، مثل:

```bash
pg_dump -Fc media_project_planner > media_project_planner.dump
```

تصدير CSV من داخل التطبيق مخصص للتقارير، وليس نسخة احتياطية كاملة.
في الإنتاج استخدم خدمة النسخ المجدولة المشفرة واختبار الاستعادة الموضحين في
`DEPLOYMENT.md`، مع نسخة خارج الخادم وتنبيه عند الفشل.
